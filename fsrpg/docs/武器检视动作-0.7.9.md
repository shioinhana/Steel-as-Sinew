# 0.7.9 武器检视动作

本轮为单手西洋剑、双刀、长枪、弓各制作三个独立检视动作。用户所说的“双手剑”沿用当前实际装备方式：主副手各一把剑。原攻击、待机、第一人称 FSVOXEL 文件及物品挂点不修改。动作是可配置、可逐渲染帧采样的骨架覆盖层，调用链继续提交玩家实际 ItemStack 的官方渲染状态。

| 武器 | 稳定 ID | 名称 | 时长 | 动作内容 |
| --- | --- | --- | --- | --- |
| 单剑 | `rapier_inspect_flourish` | 挽剑花 | 5.8 秒 | 外侧提腕，前臂引导两段不同方向的剑花，腰部反向承接，立刃收回 |
| 单剑 | `rapier_inspect_blade` | 举刃巡锋 | 5.0 秒 | 提剑到眼前，转动刃面，视线沿刃巡查，再放回 |
| 单剑 | `rapier_inspect_salute` | 立剑致意 | 4.4 秒 | 剑身竖直提至面前，轻点头，向外舒展后归位 |
| 双刀 | `dual_inspect_scrape` | 交刃摩擦 | 5.6 秒 | 两刃前方相交，双手沿各自剑轴反向滑动，两次擦刃后分开 |
| 双刀 | `dual_inspect_roll` | 双刃轮转 | 5.4 秒 | 左右两臂错峰提腕、翻转，胸腰随手势交替承重 |
| 双刀 | `dual_inspect_cross` | 交剑展锋 | 4.6 秒 | 双剑交叉上举，侧转观刃，向两侧展锋再回收 |
| 长枪 | `spear_inspect_flourish` | 双握舞枪 | 6.4 秒 | 从腋下向外绕出，双手收窄握距，胸前斜上、斜下八字舞枪，再外绕归位 |
| 长枪 | `spear_inspect_balance` | 横枪校衡 | 5.3 秒 | 横枪举到胸前，双手沿杆改变握距、左右校衡，平稳收回 |
| 长枪 | `spear_inspect_edge` | 立枪观镞 | 5.0 秒 | 先横向绕到前方，再立枪观镞、微转枪面，先恢复横枪再收回 |
| 弓 | `bow_inspect_string` | 指检弓弦 | 5.0 秒 | 左手托弓，右手靠近弦面轻触两次，放松后回位 |
| 弓 | `bow_inspect_limb` | 翻弓巡臂 | 5.4 秒 | 左手转弓呈现两侧，右手分段沿上下弓臂检查 |
| 弓 | `bow_inspect_sight` | 抬弓校线 | 4.7 秒 | 举弓对照视线，稍作左右倾斜，未引箭即放下 |

普通动作进出各 0.8 秒，舞枪各 1 秒。首末采样精确返回传入的 READY 姿态；中间关键帧和进出权重都使用五次平滑曲线。检视只改变可视骨架，不产生攻击事件、不消耗体力、不调用弓箭使用或发射流程。格挡、攻击、移动、受击等中断由运行时调度器优先处理，覆盖层没有阻止中断的状态。

## 数据和接口

- 打包模板：`src/main/resources/assets/fsrpg/animations/weapon_inspections.json`。
- 可选外部覆盖：`config/fsrpg/weapon_inspections.json`。
- 校验约定：`schemas/weapon_inspections.schema.json`；Java 还校验重复 ID、时序递增、0/1 端点、有效动作区间以及有限数值。
- 可重建作者工具：`python tools/generate-weapon-inspections.py`，仅重写新检视模板。
- 新资源不含武器几何。`right_item` / `left_item` 的局部姿态在采样前后逐项保持一致。

`WeaponInspections.actions(style)` 返回当前样式的有序动作 ID；`bow_rapid`、`bow_snipe` 和 `legacy_` 前缀映射到对应目录。`duration(id)`、`title(id)`、`spear(id)` 提供元数据。

```java
Map<String, Pose> inspected = WeaponInspections.sample(
    model, capturedReadyPose, actionId, elapsedSeconds);
```

`capturedReadyPose` 必须是开始检视时捕获的最终 READY 姿态，已完成单剑 waist 重映射、原生皮肤肩宽适配以及长枪原有双握瞄准求解。每帧继续传同一捕获值，不能把前一帧检视结果递归当作 base。覆盖层应在普通瞄准和 source 层之后执行；之后再次运行 `SpearAimPose` 会抵消舞枪。收势结束后由运行时回到当前实时 READY。

`reload(Path configurationDirectory)` 接收 `config/fsrpg`，缺失文件时写入模板；已有文件完整校验成功后才原子替换内存目录。失败保留旧目录，调用方负责显示诊断。原自定义模型及配置不被此文件覆盖。

`body` 为 `[胸部偏航, 前倾, 侧倾, 头部俯仰]`，单位度。`right` / `left` 为 `[腕 x,y,z, 偏航, 仰角, 滚转]`，长度为 FS 厘米。剑的后三项描述实际官方剑刃朝向，空手与弓描述手掌朝向；弓继续使用已有 90° 侧身根坐标。`pole` 为 `[双掌中点 x,y,z, 枪轴偏航, 仰角, 滚转, 握距]`。

胸部围绕实际腰口旋转，头部作反向补偿，腿骨承担胸部转角的 28%。若宿主另有 `supportedLower` 渲染分支，运行时需把这一腿部偏航带入最终下肢，防止其被支持解算结果覆盖。

## 持握与验证

两臂使用解析两段 IK，保留源骨长及肘平面分支；共同传递的肘关节坐标避免前臂在经过反向时选择另一个最短旋转分支。长枪先插值真实后握点、枪轴及双掌间距，再对同一根刚性枪杆中心做固定预算可达性投影，最后求两臂。不能独立钳制其中一只手，否则会离杆。

长枪舞枪的两手始终握杆，采用胸前斜向八字，不采用穿身的整圈翻杆。进出时先向外绕，立枪检视先横枪再竖起、收尾先横枪再归位。模板在普通与纤细肩宽的正前方 READY 条件下，逐帧检查整根枪杆（后方 60 cm、前方 178 cm）与胸、头、腰包络的间隔。

双剑摩擦使用实际 `legacyDualItem()` 和官方 `handheld` 显示变换计算两条刃线。主摩擦区两刃中心线间距约 **0.103 cm**；接触点处于真实剑柄前 **22–39 cm**，双手沿剑轴往复滑动。这比单纯令两只手靠近更能保证原版武器实际相碰。更改物品模型形状或资源包的官方显示变换后，视觉接触位置可能需要通过本数据调整。

`WeaponInspectionsTest` 在原四套第三人称模型上，以普通/纤细肩宽逐帧采样 120 Hz，检查完整有限姿态、精确 READY 端点、骨长、局部物品挂点、腰口、关节连续性、长枪双握与全杆避碰、双剑实际刃线接触、配置拒绝及两种弓档位映射。独立 Java 验证不代替最终 DISPLAY5 原生客户端验收。

本数据以第三人称骨架工作区标定，**不得直接用于 `_fp.fsvoxel`**：第一人称的根偏移、臂骨长度和物品变换不同，需要专门的第一人称重定向。当前完整的十二套检视验收范围为第三人称。
