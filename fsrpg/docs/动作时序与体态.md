# 动作时序、体态与过渡：0.6.0

0.6.0 处理剑类动作长期存在的三个结构问题：挥砍在判定窗口开始前就已做完、上半身侧身而骨盆与双腿正对前方、相邻动作之间没有过渡而是硬切。全部改动是运行时的，没有替换或重导任何动作资产，手持物仍是官方 ItemStack 渲染。

## 接触时序重映射

旧版 0.1.1 的每一段挥砍都在 clip 的前五分之一完成，之后保持终帧不动。运行时把这 0.4 s 的 clip 线性铺满整个前摇＋有效＋后摇，于是**伤害窗口打开时刀已经停住**。实测每段的有效帧期间刀尖平均速度只有峰值的 3% 左右。

`PoseRemap` 按实际运动分析每段 clip，得到运动窗口 `(起点, 峰值, 终点)`：以持械骨骼的世界位置逐帧求速，取 5% 峰值门限确定窗口，并要求窗口内实际位移超过 1.5 cm，否则视为没有可保留的动作（待机、开合刀等）。结果经 clip 缓存，分析一次。

权威 tick 到 clip 时间的映射改为：

| 阶段 | 映射 |
| --- | --- |
| 前摇 | 停在 authored 起点，叠加一个反向预备量，在接触开始前衰减到零 |
| 有效 | 整个 authored 运动窗口铺满有效帧；峰值时刻之前用缓入，之后按原文速度推进 |
| 后摇 | 保持 authored 终点 |

由此刀尖峰值速度落在有效窗口内，且挥砍在接触期间持续移动。前摇还有了可看的反向预备：旧资产起点本身就是伸展姿势，直接播放时前摇没有任何内容。

实测（60 Hz 采样，60 局内平均瞬时速度／峰值）：

| 动作 | 0.5.4 峰值位置 | 0.6.0 峰值位置 | 0.6.0 接触期平均速度 |
| --- | --- | --- | --- |
| `attack1_upper` | 前摇内 | 有效窗口内 | 0.27 × 峰值 |
| `attack3_upper` | 前摇内 | 有效窗口内 | 0.31 × 峰值 |
| `rapier_thrust_hit_upper` | 前摇内 | 有效窗口内 | 0.16 × 峰值 |

## 骨盆与站姿

西洋剑的侧身站姿来自 0.1.1 的运行时叠加（`-hipYaw + 65°`），实测结果是躯干朝 65° 而双腿完全正对前方：脚踝位置固定、腿骨偏航不到 1°。这是上下身不协调的直接来源。

`SwordMotion.stance` 让骨盆与双腿按躯干站姿偏航的 50% 一起转动，绕双髋中点旋转，双脚保持贴地。实测脚部偏航由 -0.8°/0.0° 变为 -32.5°/+32.5° 方向（骨盆跟随 50%），上半身没有被移动。`SwordMotion.STANCE_FOLLOW` 是该比例，常量可调。

另外加入打击倾身：接触期间躯干沿佩剑侧倾斜最多 15°，按接触进度渐入。倾斜作用在最终姿态上，因此它作用在骨盆已经跟随之后，不会把脚带离地面。

## 偏移衰减式过渡

西洋剑和双刀走 `LegacyMotion` 路径，此前**没有任何动作间过渡**：新动作从自己的首帧开始播放。实测双刀每次换段的单帧骨骼跳变是 17–19°（`left_forearm` 17.0°、`left_arm` 20.7°、`right_arm` 18.9°），因为相邻两段 clip 定义的交接姿势本身不同。

单纯在两者之间做加权混合无法消除这个跳变——两个绝对姿势之间的差就在混合结果里。`PoseLayers.OffsetDecay` 改为对**差异**做修正：

```text
offset    = log(上一呈现帧的姿势 / 新动作首帧姿势)
p(t)      = exp(offset · (1 - weight(t))) · 新动作(t)
weight(t) = smootherstep(t)，0 → 1
```

于是新动作照常播放，只是叠加一个从跳变量开始、平滑衰减到零的修正。开局一帧直接呈现上一帧姿势（权重为 0 时不施加修正，避免把跳变算两次）。修正量上限为实测跳变的 1.6 倍，保证一定收敛；同时按上限携带上一帧的速度，让快速挥砍把动量带进下一段，但一个异常帧不会支配整个修正。

实测双刀换段单帧跳变：`right_arm` 18.9° → 0.0°，`left_arm` 20.7° → 0.1°。西洋剑连招最坏单帧由 38.0° 降到 38.0°（同为 authored 动作内部，未受影响），换段处不再额外叠加。

## 验证

`swordTimingTest`（新增，379 采样 / 76 检查）覆盖：运动窗口有序且在 clip 内、五段攻击的峰值落在有效窗口内且接触期持续移动、前摇产生实际反向位移、骨盆按比例跟随站姿且不动上半身、打击倾身有界且不过度转头、换段首帧等于上一呈现帧、修正收敛回 authored 起点、整段双刀序列无换段跳变。

全量 `gradlew.bat build` 通过，既有 21 个测试项目全部保持通过（含 `spearAimPoseTest` 488825 项、`weaponAssetTest` 55342 项、`armDeformationTest` 14289 项）。

离线姿态对照工具新增：`gradlew.bat poseSheetDump -PposeSheetOutput=<路径>` 按服务端时序回放西洋剑四连、突刺与双刀连击，输出逐帧世界矩阵；`tools/render-pose-sheet.py` 渲染多视角接触表、刀尖轨迹与刀尖速度-时序曲线。这两个工具只在开发测试源集，不进入发行包。

## 已知残留

- 双刀片段内部的 authored 单帧步长仍有约 71°（`right_forearm`，位于前摇/接触交界）。这是原资产自身的跳变，0.6.0 不修改资产，因此不处理；要消除需要重新编排这几段过渡。
- 西洋剑连招在 `attack2` 入口仍有约 45° 的单帧步长，来源同上。
- 接触期速度分布依 authored 曲线而定，`attack1` 一类的前重后轻仍然明显。
