# 0.7.7：转步限位、长枪保持与持续体力回复

目标环境为 Minecraft 1.21.11、NeoForge 21.11.45、Java 21。网络协议升级到 **8**，客户端与服务端需要同版协议。完整构建、打包 JAR 的两轮实机验收、原生帧编码与官方实例部署均已完成，记录如下。

## 双刀恢复自然循环

0.7.6 恢复了原攻击曲线和线性攻击时钟，但仍沿用了一个运行时取样错误：FSVOXEL 的 `Rig.sampleLocal` 是保留端点的编辑器直接取样接口，其内部不会自动循环。把全局游戏展示时间传给该接口后，原 `walk_hold` / `run_hold` 等片段一旦超过自身时长，就会一直取最后一帧。攻击后 READY 又可能选择烘入上一击手臂末帧的 `dual_idle_XX`，使玩家看起来换一次攻击就卡到另一个姿态。

0.7.7 对标为循环的原片段先按原时长取模，再采样原曲线；一次性攻击、拔刀和收刀继续保留各自端点。READY 使用作者的 `static_idle`，行走、奔跑、蹲行和腾空继续由原对应片段驱动，兼容用的 `dual_idle_XX` 资源仍保留。没有修改源骨架或攻击关键帧，也没有恢复后来加入的攻击变速与跨动作偏移混合。

上一版实机参考取样与实际播放器共用了同一条错误路径，因此“矩阵一致”并未证明循环在长期运行后仍有动作。新版专项测试直接比较第 4、50、1000 个周期的原曲线，并检查走跑腿骨在这些时刻仍会变化；实机验收再检查实际提交的人物腿矩阵跨多个周期变化，READY 与独立取样的自然待机一致。

## 长枪和单剑的转身

角色身体转向时，下半身先直接跟随 **35%**，其余转角由骨盆追随与交替小踏步完成。相对当前武器站姿的额外腰部滞后上限默认为 **45°**；突转或持续转向超过上限时，在当前渲染帧直接带动骨盆和双脚，随后继续踏步。行走时沿用既有行走支撑与摆腿，避免额外叠加原地抬脚。

单剑保留原稿的 **65°侧身**及原骨盆分配。45°指相对此站姿的额外滞后，不代表把原 65°侧身强行改成 45°。长枪用当前帧完成两手求解后的真实胸向驱动下身，消除上一帧胸向造成的滞后；转步支撑带来的共同上下位移不累加到下一帧的持枪求解历史。皮肤、盔甲和官方物品继续共享每角色每渲染帧的同一份姿态。

## 长枪默认回收，按住保持刺出

READY 比既有腋下持枪位置再回收 **14 cm**。点按左键立即发出点刺并收回，普通点按仍为 **1 / 1 / 2 tick**，总计 **0.2 秒**。长按时在有效阶段保持伸出，展示时钟停在有效阶段末端，松开后从该位置进入正常收枪，避免长按几秒后把后摇直接跳完。

保持期间，准星经过的连续路径与角色自身移动共同形成服务端扫区判定。一次保持仍是一次已付费挥刺，对每个目标最多接触一次；拖动或持续压住目标不会自动产生新攻击或重复扣费。按下时预扣一次完整点刺费用 **10**。松开、输入续约超时、换武器、死亡或被打断会结束保持；过期或旧挥刺的拖动输入不能复活已结束的攻击。

当身体大幅转向包先到、新准星包晚一个 tick 抵达时，服务端保留尚未过期的原保持租约，暂停旧方向的伤害判定，画面枪向同时约束在角色当前前方。新的合法准星轨迹到达后继续同一次挥刺；暂停期间已经越界的旧区域不会补扫。各连续轨迹段与角色移动产生的起点共用每碰撞 tick **4096 条射线**的总预算，压缩采样时扩大保守覆盖余量，控制快速往返拖动的计算量。

第三人称矩形瞄准范围、距离、方块遮挡与两手求解约束继续适用。0.5.2 时代的“拖动后松开才扫击”不再描述当前默认操作；兼容技能 ID `spear_sweep` 仍保留。

## 体力按接触结算，战斗中半速回复

玩家等级上限与回复公式沿用 0.7.4。0 级上限 50、基础回复 5 点/秒；x≥1 时上限为 `50 + x^0.8 + 3 ln(x)`，回复为 `floor(5 + sqrt(x) + ln(x))` 点/秒。新规则只改变回复档位和攻击最终费用。

| 状态或结果 | 默认行为 |
| --- | --- |
| 不在战斗计时内 | 满额连续回复；0 级为 5 点/秒 |
| 战斗计时内 | 连续回复基础值的 50%；0 级为 2.5 点/秒 |
| 真正发出但没有接触任何目标 | 结束时返还攻击费用的 50%，不会新开或重置战斗计时 |
| 真实命中、被格挡、招架或拼刀等有效接触 | 保留完整攻击费用，并刷新战斗状态 |
| 未发出的前摇被取消 | 保留预扣的完整费用，不算已发出的空挥 |

战斗计时默认 **60 tick（3 秒）**，由真实攻击接触、受击、防御和闪避等战斗活动刷新，计时结束后恢复满额。移动本身不降低回复；已有战斗计时内的空挥仍保留原半速状态，不会把计时清零。体力不再使用旧的“消耗后完全停止回复”逻辑；灵力继续使用既有回复延迟。

接受攻击时仍要求能支付完整费用，先预扣全额，最终确定空挥后才返还。例如单剑预扣 5、完全未接触后最终扣 2.5；双刀预扣 8、未接触最终扣 4；长枪预扣 10、未接触最终扣 5。这避免以半费门槛发出本应无法支付的攻击。

弓近战和真实箭矢同样使用接触与最终结算。箭在飞行中仍可能命中，须等撞墙、消失、移除等飞行终结后才能确定是否未命中，松弦时不会立即退费；反射或穿透不会让原费用重复结算。未拉满但成功射出的箭先按原费用 70% 计算，再适用最终未命中折扣。

## 配置和升级

服务端 `config/fsrpg/combat.json` 新增：

```json
"staminaCombatRules": {
  "combatTicks": 60,
  "regenMultiplier": 0.5,
  "missCostMultiplier": 0.5
}
```

`combatTicks` 单位为服务端 tick，20 tick = 1 秒；两个倍率均须为有限的 0–1 数值。升级只补缺失字段，已有自定义值保持不变。迁移前原 `combat.json` 保存在 `stamina-combat-backup-v1/combat.json`，完成标记为 `stamina-combat-migration-v1.json`；重复启动不会重复迁移。原 `resourceRegenDelayTicks` 继续影响灵力。

客户端 `config/fsrpg-client.toml` 新增：

| 字段 | 默认值 | 范围与单位 |
| --- | --- | --- |
| `waistTwistLimitDegrees` | `45.0` | 10–90°，相对武器站姿的额外腰部滞后上限 |
| `turnRootFollowWeight` | `0.35` | 0–1，下身立即跟随身体转向的比例 |
| `spearReadyRetractCm` | `14.0` | 0–30 cm，READY 的额外回收距离 |

既有 `spearPelvisResponseTicks`、`spearTurnStepTicks`、`spearTurnStepDegrees`、`spearTurnStepLiftCm` 继续控制转步追随、时长、转角与抬脚高度。客户端参数只控制外观，目标、伤害、资源与有效时间仍由服务端判定；既有自定义动作文件不由本轮配置迁移替换。

## 边界

额外腰扭上限约束转身时的站姿滞后，不约束作者攻击本身所有局部关节，也不重画原动作。大转身触发的直接跟随是有意允许的少量下身转向，地面接触仍使用既有支撑与踏步方案；长枪在极端角度仍可能局部贴身，未承诺所有素材与任意外部模型完全没有视觉接触。

长按长枪仍保留原攻击距离、前向瞄准范围、目标遮挡和每挥刺去重，不会因为画面上经过一个目标就绕过服务端几何判断。大转身的网络夹缝内，旧包的世界方向可能已经越界，实际显示会先限制到当前前方；独立输入报告中的枪轴对旧包方向角度误差是诊断数值，不代表全程零视差或全程沿用旧方向的证明。飞行箭矢的未命中返还要等飞行终结，属于延迟结算；退出、移除和重载路径仍须保持一次性结算，最终实机覆盖范围以报告为准。
