# 双刀笔画时序

0.6.3 处理双刀的出手表现：原资产的斩击在约 50 ms 内转过两百多度，60 fps 下只有三四帧，看上去是刀光一闪，而不是挥砍。

## 原因

`legacy_dual_blade_attack*_upper` 每条 clip 0.4 s，有 110–200 个关键帧，密度集中在 0.13–0.19 s 之间。逐关键帧量得的关节转角（`gradlew dualClipAudit`）：

| clip | 60 Hz 下最大单帧关节步长 |
| --- | --- |
| `attack_1_upper` | 29.7° |
| `attack2_upper` | 69.2° |
| `attack3_upper` | 46.9° |
| `attack4_upper` | 34.2° |
| `attack_dual_upper` | 50.8° |

这是原始动作自身的速度，不是采样误差。此前版本把 clip 线性拉满整个动作区间（3/6/1 tick），所以这几十度仍原样落在屏幕上。

## 做法

`PoseRemap.warp` 为每条 clip 生成一张单调的时间映射表，按关节转速放慢 clip 时钟：

```text
rate(τ)    = max over joints of 角速度（度 / clip 秒）
density(τ) = 1 + rate(τ) / 600
t(τ)       = T · ∫density / ∫density（整段）
```

慢的部分 `density ≈ 1`，保持原节奏；越快的部分越慢，速度向 `600 × ∫density / T` 饱和而不是无限增长。原资产里"一个关键帧跳过去"的突变，因转速极大，会被摊到几十毫秒里，相当于自动补出过渡帧。曲线是连续的，没有阈值，也没有速度台阶。

总时长不变（仍由服务端 windup + active + recovery 决定），只改变 clip 时间随动作进度的分布。第一人称资产（`legacy_dual_blade_fp`）不受影响。

## 实测

60 Hz 回放，所有手臂、前臂、双刀关节取最大单帧转角：

| clip | 线性 | 0.6.3 | 最大步长所在 tick |
| --- | --- | --- | --- |
| `attack_1_upper` | 29.7° | 14.5° | 4.67 |
| `attack2_upper` | 69.2° | 26.7° | 4.33 |
| `attack3_upper` | 46.9° | 17.9° | 3.67 |
| `attack4_upper` | 34.2° | 16.7° | 4.67 |
| `attack_dual_upper` | 50.8° | 19.1° | 3.33 |

最大步长都落在有效窗口（tick 3–9）内。五段连击序列里 clip 内最大单帧步长由 71° 降到 26.7°，换段帧跳变仍为 0°。

## 验证

`swordTimingTest` 新增 `dualStrokeIsReadable`：映射保持两端、clip 时间从不回退、最大单帧步长下降到线性的 60% 以下且低于 30°、最大步长发生在有效窗口内。连击序列的 clip 内步长上限由 75° 收紧到 35°。

`gradlew dualClipAudit [-PauditFilter=<片段>]` 列出每条 clip 的关键帧时间与相邻关键帧间最大转角，用于以后继续整理资产。
