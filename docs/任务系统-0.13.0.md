# 公会任务系统 0.13.0

Minecraft 1.21.11、NeoForge 21.11.45、Java 21。J 打开原收集页，点击“公会任务”进入新任务板；也可输入 `/fsrpg guild`。任务由服务器计数、限制接取并发奖励。

## 玩家使用

- 任务板显示难度、最低称号、目标和各类奖励。每日、晋升、进行中、已完成、失败和放弃分别可查。
- 默认最多追踪三条任务；HUD 分别显示目标进度。取消追踪保留任务；放弃需再次确认，完成任务不能放弃。
- 物资募集按背包当前数量实时检查，取走材料会取消完成状态；旧教学任务继续累计接取后的物品拾取。两种模式领奖均不消耗物品。
- 完成后领取配置的实体货币、道具、经验和声望；自选奖励须选一项。随机奖励按权重抽取，同一次记录不能重复领取或重抽。
- 连环委托先完成并领取当前阶段奖励，再推进下一阶段；全部阶段奖励和最终奖励分别只领一次。
- 冒险者初始为 D 级。默认完成三次任务且完成过物资募集后，到公会接待员八格内申请 C 级考试；完成考试后回到接待员处领奖才晋升。B/A/S 默认需要累计 8/15/25 次完成和各自考试。物品栏中的冒险者牌不直接授予称号。
- 每日按 `guild.json` 的时区零点刷新，默认每日从池中固定选三项；首次查询按当前称号和前置筛选，当天重开、重启或晋升均不会重抽。跨日未完成的旧日常失效；已完成待领奖的旧日常可继续领奖。

## 公会和 BOSS 设置

讲台默认作为任务板。给任意 NPC 加 `fsrpg_guild` 标签，或将其自定义名称设为“公会接待员”，即可右键打开任务板并办理考试；服务器检查实际距离。普通任务板不能代替接待员办理考试或晋升。

`guild_access.json` 可调整 NPC 标签/名称、任务板方块和考试距离。`guild_bosses.json` 可指定 BOSS 种类、自定义名称、维度、坐标、等级、精英标志和重生间隔。模板的自动刷新默认关闭；设置实际地点并开启对应 `enabled` 后生效。只在对应区块已加载时生成；存活实体 UUID 在世界账本中保留，卸载区块不会重复生成。

原版凋灵、末影龙，以及有 `fsrpg:boss` 标签或持久数据 `fsrpg_boss=true` 的实体属于 BOSS。真实造成伤害、五分钟内仍在同维度 128 格内的在线参与者，可各自获得符合其任务条件的讨伐进度；最终一击为环境伤害时也检查参与者。没有参与的附近玩家不计入。

怪物等级读取服务端实体持久数据 `fsrpg_level`（缺省 1）；精英读取 `fsrpg_elite=true` 或 `fsrpg_elite` 实体标签。任务可进一步要求指定标签、等级上下限、自定义名称和击杀地点。怪物讨伐与玩家悬赏分别判定。

## 创建与修改任务

编辑实例 `config/fsrpg/quests.json` 后执行 `/fsrpg reload`。管理员也可用 `/fsrpg questCreate <完整单行JSON>` 创建新 ID 的任务；完整校验通过才保存，原配置备份为 `quests.json.bak`。已有 ID 应编辑原定义，保持任务、目标和阶段 ID 稳定。字段定义见 `schemas/quests.schema.json`；默认示例见 `src/main/resources/defaults/guild_quests.json`。

```json
{
  "id": "custom:wood_and_iron",
  "label": "木材与铁矿补给",
  "description": "准备两种材料，领取公会补给奖励。",
  "objectives": [
    {"id":"wood","type":"COLLECT","target":"minecraft:oak_log","count":20,"inventory":true},
    {"id":"iron","type":"COLLECT","target":"minecraft:raw_iron","count":10,"inventory":true}
  ],
  "rewards": {
    "currency":[{"id":"fsrpg:silver_coin","count":5}],
    "items":[{"id":"minecraft:bread","count":3}],
    "reputation":10
  },
  "repeatable":true,
  "rules":{"minimumRank":"D","difficulty":"普通","completionCooldownSeconds":300,"abandonCooldownSeconds":30,"allowReacceptAfterAbandon":true}
}
```

| 配置 | 用法 |
| --- | --- |
| `rules.minimumRank` | D/C/B/A/S 称号门槛，服务器验证 |
| `rules.difficulty` | 独立的显示难度，可用简单、普通、困难、S级等文字 |
| `rules.bountyTier` | NONE/NORMAL/HIGH/S；非 NONE 仅接受 PLAYER_KILL 目标，与难度独立 |
| `criteria.playerUuid` | 玩家悬赏目标 UUID；省略时匹配其他玩家，自杀不计 |
| `criteria` | minLevel/maxLevel/elite/requiredTag/entityName/boss |
| `location` | VISIT 的到达地点，或 KILL/PLAYER_KILL 的击杀地点球形范围 |
| `rewards.currency/items/choices` | 实体货币、固定道具、任选一项道具的独立列表 |
| `rewards.randomPool` | `{item:{id,count},weight}` 列表；randomRolls 默认 1，最多 16 |
| `rules.stages` | `{id,label,rewards}` 列表，目标用 stage=0、1…归属阶段 |
| `rules.timeLimitSeconds` | 0 不限时；到期失败，不能正常领奖 |
| `rules.completionCooldownSeconds` | 领奖后独立冷却 |
| `rules.abandonCooldownSeconds` | 放弃或失败后的独立冷却 |
| `rules.allowReacceptAfterAbandon` | 是否允许失败/放弃后重接，省略为 true |
| `rules.daily` | 加入每日候选池；实际每日数量由 guild.json 控制 |
| `guild.json` | maxTracked、dailyCount、timezone、promotions；晋升支持总完成数和指定任务次数 |

`/fsrpg accept <id>`、`claim`、`abandon`、`track`、`untrack` 可操作普通任务，`/fsrpg exam` 申请当前晋升考试。阶段和自选奖励使用界面操作。

## 存档和升级

任务状态、目标、历史、每日分配、奖励领取标记、称号和声望按 UUID 存在世界 `data/fsrpg/quests.json`。每任务存档保留最多 64 次历史，界面同步最近 8 次详细记录及必要终态摘要，防止长期任务记录超出网络包上限。schema 1 自动迁移为 schema 2，旧任务 ID、目标 ID 和完成次数保留；旧原文件另存 `quests.json.schema1-backup`。网络协议升至 14，服务端和客户端使用同版。

首次升级仅向旧配置追加缺失的 18 个公会任务；同 ID 用户定义保持原样，原任务配置备份在 `quest-system-backup-v1/`，已有全局公会配置保留。修改配置不得直接修改玩家进度文件来决定完成或奖励。

本轮清理了旧验收逐帧缓存和旧构建中间文件，共约 80.091 GB。历史成片、报告、独立场景截图和每序列首中末样本保留；旧报告中的完整帧序列路径现仅代表当时采集记录。详见 `verification/CACHE-CLEANUP-20261101.md`。
