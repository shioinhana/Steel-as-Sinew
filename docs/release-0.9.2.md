# 0.9.2：移动视角卡顿优化与长枪横杆格挡

目标环境：Minecraft 1.21.11 / NeoForge 21.11.45 / Java 21。开发版本 **0.9.2**，网络协议仍为 **12**（无新增消息，快照字段不变）。

本轮只改客户端镜头/呈现与长枪格挡姿态，不改战斗数值、输入键位、服务端判定或配置默认值。

## 1. 移动视角卡顿：定位与优化

在 DISPLAY5 复制世界用真实客户端走跑并持续转动越肩镜头（1600×900、120 FPS 上限、HUD 开启）测量每个原生渲染帧：

- 改写前：每帧镜头安全裁剪做 **两次** 八角扫掠（16 次 block clip）；改为先平滑轨道偏移、再对最终偏移做 **一次** 八角扫掠（8 次），墙内保护不变。实测镜头函数平均约 **10–12 µs/帧**，最大约 **145 µs**，属于极小开销；不是卡顿主因，但每次减半仍有收益。
- 新增**镜头距离平滑**：障碍物靠近时立即收近（绝不穿墙），离开障碍后以 0.10 秒时间常数缓出，避免跑过墙角时镜头每帧跳变。实现为纯逻辑 `CameraClipSmoother`，含 16 项边界测试。
- 武器档位解析增加**快照版本缓存**：此前 `style()` 在角度事件、鼠标事件和镜头位置中每帧重复扫描 JSON 数组；现在每个快照版本只解析一次。
- 保留可复现的镜头性能采样（`CombatCamera.perfSnapshot()`、`ClientState.perfSnapshot()`），供 DISPLAY5 报告记录真实每帧镜头裁剪与快照解析耗时。

**测量与真实瓶颈**：120 FPS/HUD 实测中位数约 **8.42 ms**，p95 约 **9.6–11.1 ms**，p99 约 **10.2–15.1 ms**；每 10 秒各出现 1 帧 31–47 ms 的孤立长帧。镜头裁剪只占约 10 µs/帧，快照解析最大约 1.5 ms。JFR 41 秒采样显示 **71 次 G1 暂停、中位 5.4 ms、p99 19.4 ms、总暂停 395 ms**，主要由原版资源/区块生成和堆分配驱动；这是剩余卡顿的地板，属于 JVM/GC 与区块加载，不在镜头逻辑内。建议本机启动器把 `-Xms`/`-Xmx` 配成固定值（如 2G/4G）并关闭后台 CPU 竞争；Mod 本身不再对每帧做重复 JSON 或重复裁剪。

## 2. 长枪格挡：横执枪身

此前长枪格挡仍沿用瞄准求解，枪尖朝前、镜头里几乎只看得到枪尾；现在格挡阶段不再调用瞄准 IK，改为**双手横杆防御**：

- 在胸口高度（实测约 137 cm）建立一条身体横向的枪杆线；
- 用闭式双骨 IK 把双手放到枪杆线上（实测手腕到目标误差 < 0.001 cm），肘部以胸前方为极向量；
- 按官方 `spearCarrier` 的真实枪杆轴（模型空间 `(-X,-Y)`）转腕，使枪杆真正横在身体前方；
- 格挡结束回到原有瞄准/待机时继续使用原求解，不影响刺、扫、Ready 姿态与服务器格挡判定。

DISPLAY5 前后视角截图确认枪身横向挡在胸前，纯 Java 测试确认双手可达且高度在胸段。
