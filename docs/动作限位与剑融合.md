# 动作限位、旧剑上半身与轻微移动倾斜：0.5.3

本轮处理长枪框内瞄准引发角色转到另一侧、移动倾斜过大、剑上下身未使用新版调度及动作体力过高。版本仍为 Minecraft 1.21.11 / NeoForge 21.11.45 / Java 21；没有引入新的动作素材。

## 长枪显示框与实际方向

`SpearAimField` 同时供客户端和服务端使用：相对角色左右各 45°、绝对俯仰上下各 40°。第三人称相机俯仰限制为上下各 24°，保留边缘外移动转向。这按用户追加要求，将之前 15°/20° 的左右范围扩展至 3 倍、上下范围扩展至 2 倍。

`SpearCursorField` 根据实际视野角、窗口比例、相机旋转和相机到眼睛的位移求可操作矩形。现有 `spearCursorWidth/Height` 数值保留，屏幕最大尺寸运行时按 3 倍/2 倍扩展并夹到视口 96%，避免原高度 0.5 配置截断扩大效果；框顶、底分别收缩，再计算左右边界。框的射线在近端前方 4.5 格平面与远端均须处于保守方向棱锥中，连续矩形内部因此也有效。输入、HUD、瞄准拾取读取同一矩形。角度倍率不等于投影像素倍率；典型 1280×720、FOV 65、相机后移 4 格时，框由约 160×218 扩大到 598×502 像素。

框内鼠标不改变角色的 `getYRot()`，超出框的剩余位移才改变相机和角色朝向。视野角或相机变化缩小框时，先重新夹入旧光标再处理新鼠标位移，不把框的缩小当成转身输入。

本地长枪框模式还把当前与上一帧身体渲染角对齐到该角色朝向。实机侧移曾让原版 `yBodyRot` 偏到约 -25.5°，使已在框内的目标被动画层相对身体的 15° 上限再次夹偏约 1.8°；只限制鼠标角度不能消除这一问题。现在相机、外层身体、求解器和服务端使用同一前方基准，保留正常 WASD 移动、支撑脚和边缘外转向。

拾取检查完整实际屏幕射线，保留方向合法的近处方块和实体，只忽略角色侧后方/范围外的相机遮挡。近处命中保持真实眼睛到目标的 yaw/pitch，服务端据此执行距离、方向和视线判定；动画瞄准距离沿这个相同方向延长至前向至少 4.5 格，避免过近有限目标触发转胸。求解和网络包使用这个安全动画点。手部与眼睛位置不同，因此渲染枪轴不保证严格穿过原近处命中点；实际伤害方向仍指向命中目标。

边缘外转向会丢弃已经不在当前身体前方范围中的旧扫击轨迹点，服务端拒绝范围外轨迹。非本地 READY 使用同一角度范围和前向深度；READY/WINDUP/RECOVERY 的球面方向交接也夹回该范围，避免两个合法上缘方向之间的球面中点越过俯仰上限。ACTIVE 仍使用服务端已接受的世界轨迹。扩大范围后，实际动作求解在共同握点投影之前，将每次胸部附加转角解析投影到实际前方 89° 边界，保留目标方向、原动作俯仰/侧倾和肘腕约束。

前方停止角按目标的身体前向深度连续释放，避免角度刚超出框时突然解除约束；真实框内目标前向深度至少 4.5 格，仍执行完整 89° 限制。独立工具使用的通用 IK 接口保留近处与后方目标求解，历史交接数据按原样通过回归；实际玩家与宽范围专项使用带动作历史的前方约束路径。

物理鼠标钩子仅在游戏窗口活动时处理输入，成功消费位移后清空原版累积值，防止取消原版处理后重复使用旧位移。开发实机脚本单独隔离外部物理鼠标，并记录脚本输入与实际框、溢出和朝向变化。

## 旧剑上半身与新版下半身

旧上半身来自 ActionCombat 0.1.1 的 `ysm_player.animation.json`，通过既有 `tools/import_legacy_011.py` 转换为 `legacy_rapier.fsvoxel`。四段 `*_upper`、静态持剑、突刺和既有特殊动作继续读取原资产；本轮不修改原资产或覆盖外部自定义模型。[来源记录](../verification/action-limits-20261013/sword-source.json) 保存原文件和导入资产 SHA-256。

之前 `LegacyMotion` 同时混入旧 walk/run 上半身并提前返回，使剑绕过新版动作交接和支撑脚。现在 `SwordMotion` 读取旧静态上半身与实际攻击，接入共同渲染时钟、动作交接、运动平滑和 `Locomotion.supported`。下半身的站姿模板取当前长枪实际 `rapier_stance`，移动时使用相同的步态、支撑脚和上下半身权重。

旧骨架的 torso-center 原点通过腰部转换移至当前运动层的腰部原点，补偿所有 body 直系子骨的偏移，保留头、手臂、物品定位器的世界矩阵。全局额外移动倾斜至多 4°，剑骨盆偏移至多 1.5 cm、步态上半身反馈为原权重的 20%。原招式本身的倾斜和手持物官方 ItemStack 渲染保持。已有客户端自定义数值留在文件中，额外移动层运行时执行 4° 上限。

## 体力成本与配置迁移

所有动作体力成本为升级前的 20%：`skills.json` 的技能、`styles.json` 的轻重与完美格挡、`combat.json` 的回退格挡和闪避、`archery.json` 的速射/狙击/撞击。拔收刀本来不扣体力，继续为零。服务端资源门槛和实际扣费读取同一套迁移后的定义，不叠加第二个倍率；灵力、上限、恢复、时序、伤害与其他配置值不变。

首次迁移在默认种子和旧技能迁移之前保存已有成本文件；按稳定技能/档位 ID 只缩放原有成本字段，新默认值已是 20%。整集解析通过后原子写入改变的成本文件，再写 `stamina-cost-migration-v1.json`。原文件在 `stamina-cost-backup-v1/`，中断重试仍从原快照计算，完成后的 reload 不再降低。随后用户编辑的成本就是实际扣费。

官方配置暂存验证了 41 个体力字段，全部精确乘 0.2，其他 JSON 值一致。实际只需替换 `combat.json/skills.json/styles.json`；弓成本原来全为零，文件字节不变。[暂存报告](../verification/action-limits-20261013/stamina-stage.json) 包含迁移前后哈希和重载幂等检查。
