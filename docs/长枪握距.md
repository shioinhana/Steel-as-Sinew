# 长枪握距：0.6.1

0.6.1 只做一件事：把握距从常量改成逐帧解算。长枪此前两掌恒定相距 58 cm（`SpearAimPose.GRIP_SPACING`），整根枪像一块刚体一起平移——刺击时后手无法沿杆前滑，扫击时也无法收拢双手换取力臂。真实枪术两者都做。

## 动态握距

`SpearGrip` 按帧求出实际使用的握距：

```text
authored = |右掌世界位置 - 左掌世界位置|     （取自当前实际骨架世界矩阵）
travel   = 瞄准距离(cm) + 原动作位移量(cm)
drive    = tanh(travel / 45)
spacing  = clamp(authored + (70 - authored) · drive · 0.65, 44, 70)
```

要点：

- **基准是 authored 握距**，不是写死的 58。外部自定义模型或后续资产若本身用更窄或更宽的持握，会被如实沿用；rig 缺少任一手时回落到 58。
- **驱动器是行程**。静止持枪（travel≈0）握距完全等于 authored，因此待机、行走、跑步的持枪结构不受影响；一旦开始发力，握距随行程平滑变化，`tanh` 保证连续且斜率有界。
- **上下界 44–70 cm** 都夹在单臂可达范围内，且纵向可行区间由求解器自己再检查一次，不可行时仍走原有异常路径。
- 握距并入 `SpearConstraints.Limits`（新增 `gripSpacingCm`，默认 58），因此求解器内部六处使用点（前掌 IK 目标 4 处、`closedRear` 与 `longitudinalRange` 的可行性区间 2 处）都读到同一帧的同一个值。旧构造签名全部保留并转发到 58，既有调用点与测试无需改动。

调用点在 [PlayerAnimations.java:504](../src/main/java/org/fsrpg/client/PlayerAnimations.java#L504)，发生在瞄准交接之后、求解之前，与 `withCarry(carrying)` 同一条链。

## 验证

`spearGripTest`（新增，1772 采样 / 1781 检查）覆盖：握距由骨架实际掌距测得、静止持枪保持 authored 值、发力时握距变大且连续（每 0.5 cm 行程的增量小于 0.5 cm）、48 组 authored×行程组合全部落在带内、越界与非有限值被夹取。

长枪相关专项同时复跑通过：`spearAimPoseTest` 488825 项、`spearForwardFieldPoseTest` 前方范围姿态、`spearTurnTest` 22279 项、`torsoConnectionTest` 7182 项、`poseLayersTest` 6037 项、`presentationMotionTest` 649 项。这些测试构造自己的 `Limits`，因此仍以 58 cm 运行，可作为「默认行为未被改写」的对照。

## 本轮未做

- **躯干扭转分配**。求解器仍然只写 `body` 一根骨，`chestHeadingLimit` 前方上限仍是 89°（近处/后方目标平滑放宽到 180°）。把一部分扭转交给骨盆需要同时改测试口径——现有测试断言的是胸部**世界**航向 `<= 89.03°`，而骨盆参与后应当断言的是胸部相对骨盆的角度。这属于 0.6.2 的骨架分段工作，本轮不动。
- **肘部极向量的解剖参考**。`armCandidate` 仍按代价评分选择两个 IK 根，候选代价里没有「肘尖应朝下外」这一项。
- **瞄准驱动的下肢站架**。下肢仍只有转步与支撑脚求解，没有随俯仰/左右负载的站架。
