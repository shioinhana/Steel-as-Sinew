# 长枪性能与体力回复（0.7.2）

长枪卡顿主要发生在每帧安全握点搜索：大量候选重复计算同一手臂碰撞，已被解剖连续性排除的肘分支仍做完整碰撞评分，盒相交热路径还反复动态读取向量分量。JFR 首轮实机 2803 个渲染线程样本中，1710 个落在盒相交调用链，其中 Vector3f.get 叶节点 1267 个。

本版缓存候选碰撞，延迟未使用分支的评分；对候选右臂完成后的非负成本、只增大的峰值转角作保守下界，排除必败前手搜索。盒相交展开三个固定轴，合法环内投影直接返回原零距离候选。保留原评分顺序、搜索终止、握距、关节限位、避碰余量和最终解算；每个真实渲染帧仍独立采样。

## 实机对比

同一原始复制世界各生成一份带标记测试世界，真实发行 JAR、官方 ItemStack 渲染、本地玩家、DISPLAY5、1000×680、视距3、VSync关闭。每场景热身3秒，随后8秒逐 RenderFrameEvent.Post 记录原生时间戳；计时段不录屏、不额外求解姿态，截图只在热身。旧版0.7.1与新版0.7.2各有完整JFR和报告。

首轮旧版遇并行开发负载，空手约319FPS；重测旧版空手约747FPS，新版空手约520FPS，说明后台/JIT/调度仍有波动。以下使用停止代理CPU任务后的旧版复测，不把空手变化算作优化效果。结果仅代表本机测试场景；极端近目标离线轨迹仍可出现约60–70ms求解，实机也有偶发超过50ms帧，本版没有宣称彻底消除所有尖峰。

| 场景 | 旧版FPS | 新版FPS | 旧版P95 ms | 新版P95 ms |
| --- | ---: | ---: | ---: | ---: |
| 长枪待机 | 118.4 | 206.5 | 10.15 | 6.61 |
| 横纵扫瞄 | 75.5 | 158.4 | 22.85 | 9.93 |
| 方向移动 | 105.0 | 195.4 | 12.12 | 7.11 |

完整报告在 `verification/spear-performance-20261016/comparison.json`；原始 native 时间戳、截图和JFR分别在 baseline/、baseline-repeat/、optimized/。优化版四个长枪场景均超过30Hz，并观察到同一游戏tick内不同原生姿态。

## 结果等价与回归

真实模型六条60Hz轨迹、540帧、八个上身关节的矩阵与旧版逐位相同（包括待机、刺、扫及连续瞄准）；源代码哈希、矩阵哈希与分配量在 micro/comparison.json。微基准连续扫瞄临时分配约减少30%–37%，离线均值受并行构建影响，实机性能以逐帧报告为准。

完整 `gradlew.bat build` 通过；另含200000项盒相交平行/边界等价检查、3715725项评分下界完成比较、488825项持握/限位检查、2400项标准/窄肩腋下持握检查和既有剑、双刀、下肢、HUD、生物素材与服务端回归。开发 smoke 与 monitorAgent 不进入发行JAR。

## 体力与部署

基础体力回复 1→3点/秒。既有配置首次升级时将当时值乘3，新配置直接3；保留灵力回复1点/秒、回复延迟20tick、上限、消耗与成长倍率规则。53项专测覆盖20Hz服务端回复、定制值、仅一字段变更、原字节备份、重载幂等、升级中断重试与非法配置修复。

原配置保存到 stamina-regen-backup-v1/combat.json，完成标记 stamina-regen-migration-v1.json 阻止再次放大。正式配置在副本迁移并逐文件校验后才部署，JAR、combat、标记与备份一起安装。旧发行JAR及完整原配置另存实例的带日期 fsrpg-backups 目录，保留其他Mod、选项、自定义模型与用户世界。部署脚本 tools/deploy-spear-performance.ps1 会核对实际游戏目录、NeoForge版本、游戏进程与发行SHA-256。
