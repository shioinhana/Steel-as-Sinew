# 动作系统融合：0.5.2

0.5.2 合并 0.5.0 的原动作、呼吸、步态、跑姿与移动重心，以及 0.5.1 的双手刚性闭合、正向肘曲、腕部限位和避碰。最终选用 trial-30：原动作先完整采样，再求解长枪约束，修复连续求解逐帧抵消手臂动作的问题。本轮沿用现有 FSVOXEL 动作文件、官方皮肤与 ItemStack 渲染，未加入新动作素材。

[长枪动作求解](长枪动作求解.md) 保留 0.5.1 的研究、八项原始论文/官方实现及历史验证；以下数值来自最终 0.5.2 专项和实际客户端，不沿用旧版通过结果。

## 统一动作流水线

所有武器共用连续渲染时钟：在 `RenderFrameEvent.Pre` 按 Minecraft 原生帧时间增量推进，攻击相位、呼吸、动作交接和步态读取同一时间轴；皮肤、盔甲和手持物共用当前帧。西洋剑、双刀和弓保留原动作采样路径，提前返回，不进入长枪 IK。

长枪依次叠加原动作、呼吸、READY 跑姿、动作交接、步态、移动倾斜、重心和支撑骨盆，适配普通/纤细皮肤肩部位置；完成瞄准交接后，`SpearMotion` 准备目标与历史，`SpearAimPose` 求解共同握点、胸转和两肘分支，最后提交完整世界矩阵。保留原动作的胸部位置和倾斜。现有 `spear_run` 枪轴约向上 5°，继续沿用。

WINDUP 在有效帧前完成瞄准交接，预留 `min(0.5, deadline / 6)` 个原生 tick；ACTIVE 精确使用服务端轨迹。交接优先沿三维方向作球面插值；只有整段路径都处于可表达的 ±80°俯仰范围才使用它，越过极区时整段使用连续的 wrapped-yaw/pitch 路径。目标距离也连续交接。

## 目标、原动作历史与实际历史

0.5.1 强烈偏好上一实际姿态，原动作握点权重较低；避碰搜索撤销小幅动作后，再以撤销结果作为下一帧起点，会持续消除原动作。0.5.2 将动作目标、跟随动作的软历史和真正上一帧分开保存。

第一次成功提交建立固定掌心修正。修正随原动作胸部方向传输，完整腕转只进入软连续性，避免腕部旋转把数十厘米 IK 偏移变成额外掌心圆弧：

```text
palmLocal = (0, -6.25, 0) cm
rawPalm = currentSource[right_hand] * palmLocal
correction = anchorSolved[right_hand] * palmLocal
           - anchorSource[right_hand] * palmLocal
bodyDelta = currentSource[body] * inverse(anchorSource[body])
fixedTarget = rawPalm + bodyDelta.transformDirection(correction)
carriedTarget = previousSolved[right_hand] * palmLocal
              + rawPalm - previousSource[right_hand] * palmLocal
f = READY ? authoredFidelity(finalAim, bodyYaw) : 1
rearTarget = (1 - f) * carriedTarget + f * fixedTarget
```

`transformDirection` 只传输修正向量，原始掌心已经包含平移。READY 在正常前方保留固定锚点，极端方向携带上一实际可行握点并继续原始掌心位移；中间方向平滑混合。WINDUP、ACTIVE、RECOVERY 保持固定锚点，避免把搜索后的握点位移累积进招式。三参数 `prepare` 默认固定锚点；生产四参数入口在最终瞄准交接之后调用。

`authoredFidelity` 根据名义瞄准相对玩家身体的方向计算：`cos(aimYaw - bodyYaw) * cos(aimPitch)`，前方夹角 ≤50°为 1，≥80°为 0，中间平滑过渡。它不读取原动作转胸、求解后转胸或试验握点视差。求解目标权重为 `0.12 + (256 - 0.12) * fidelity`；低 fidelity 仍使用融合求解，枪杆、深手臂接触和实际时序权重不降低。

软历史对身体、头部和左右上臂、前臂、手部八骨分别计算：

```text
continuity[bone] = currentSource[bone]
                 * inverse(previousSource[bone])
                 * previousSolved[bone]
```

它以 0.08 权重评价原动作以外的额外修正。另一份 `actual` 保存真正上一完成帧，以世界朝向评价上臂、前臂、完整手部、胸部与头部变化，原动作传输不能掩盖实际跳变。运动量来自原始掌心/胸部位移及角变化，角度以 20 cm 杠杆换算为厘米；不把未解决的锚点偏移当作新动作。

同一 `renderTick` 重复 `prepare` 始终读取上一完成帧；重复 `commit` 只替换本帧结果，不推进自己的历史或重建锚点。同资产动作交接保留状态；换世界、清理、重载模型或帧时钟回退会重建历史。胸部种子跟随原动作，READY/RECOVERY 按已有配置逐步放松额外 yaw。

## 约束与候选选择

两手保持 58 cm 间距、真实枪轴和固定骨长；默认正向肘曲 10–135°、优先腕转 120°、绝对腕转 150°、颈部偏航 85°、极端俯仰侧倾 18°、避碰余量 1.5 cm。肘与腕硬边界先收紧共同握点可达域，不能在闭合后分别夹两只手。

每项候选先从自身握点看向有限距离目标，迭代完成共同闭合并检查收敛，再评价原动作、接触和真实历史。保留实际上一握点投影后的候选；必要时搜索邻近和其他连通环。舒适胸转困住深接触分支时，另求一项从真实上一胸部侧起步、只满足精确可达的完整姿态，两项闭合后比较，不递归生成更多胸部备选。闭合阻尼通常为 0.8，仅振荡时降至最低 0.15。

融合路径枪杆接触权重 36000、深手臂接触权重 18000，原保守手臂评分权重 180 保留。深接触项用半径 3 cm 的骨段代理，上臂排除近胸端 32%，区别保守袖子外壳与深穿。实际超预算罚权为 100000；预算是 `10 + min(75, 1.1 * targetDirectionStep + 0.6 * sourceMotion)`。目标步长从上一实际掌心看向本帧目标计算，试验握点不能为自己增加预算。无原动作传输的旧入口保留原参数。

trial-30 对所有完整候选统一分级：真实身体、头部及六个手臂关节的峰值 ≤89°的候选优先，再在该类比较原有评分；没有此类候选时优先减小峰值，近似并列再比评分。全局/局部握点、实际历史热启动、连贯补充搜索和完整胸部备选都遵守这一顺序。小幅瞄准的 35°复核门槛保持。两肘分支仍在两项实际峰值均不超过 `max(35, motionBudget + 1)` 时允许按接触代价选择，否则优先实际历史更近的分支。

骨骼写入比较两套等价 XYZ 欧拉角经实际 `Pose.fsQuaternion()` 重建后的误差，避免接近 180°时浮点半角精度影响闭合。握距和枪轴误差门槛仍为 0.03 cm，未放宽。
